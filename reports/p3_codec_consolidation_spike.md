### 1c. Term serialization — TWO wire formats (codec census gap)

* `mlopt_core.ir.term_to_data`/`term_from_data` (`eqsat/.../ir.py:497`)
  — `{"op","args","attrs"}` / `{"var"|"param","shape"}` / `{"const"}` /
  `{"mvar"}` records.  Used by `mlopt/stage.py` records, `rulecache`,
  and **`vocab/laws.yaml`** (the 146-law bank serializes in this
  format).
* `mlopt_discovery.hnl_codec.term_to_json`/`term_from_json`
  (`hnl_codec.py`, 479 lines) — the kernel `Term` externally-tagged
  envelope (`{"Op"/"Arr"/"Const"/"Opaque"}`) + ADR-0173
  `__nonfinite__`/`dag.program` conventions.  Used at the
  `.hnl`/kit boundary (`mlopt/adapters/hnl.py`).

These are not interchangeable: `term_to_data` carries `TensorType`
shapes on leaves and mlopt attr spellings; `hnl_codec` carries kernel
`Term` semantics (attrs via `lit.__mlopt_attrs__` until the
`Term::Op.attrs` channel is adopted — the field has landed
upstream).  **P3 must pick one canonical term serialization** —
recommendation: `hnl_codec`'s kernel-Term envelope wins (it is the
ADR-0172/0173-sanctioned wire); `term_to_data` survives only as a
*view* codec inside `mlopt_core.ir` until the IR itself demotes.

`mlopt/stage.py`'s lift/search/verify/deliver record schema is a
third, informal JSON protocol — unversioned, built on `term_to_data`.
Needs a `schema:` pin (same convention as `vocab/*.yaml`) whenever the
record format is touched.

`vocab/` (projection, not source). The deeper duplication is
**three term representations** (`mlopt_core.ir`, kernel `Term` via
`hnl_codec`, `lib_kernel_ir.Term`) and **two term wire formats**
(`term_to_data` vs `hnl_codec`) — those are the real P3 targets.

## 2. `mlopt_core.ir` demotion path — what engine-eqsat must replace

### Current search path

```
Source.to_ir ──► mlopt_core.ir.IR ──► Optimizer.search
   (torch.export FX lift / OnnxSource / hnl codec / carriers)
        │                                    │
        │                            EGraph (Python, default)
        │                            or engine=NativeEngine
        │                            (mlopt_native — same semantics, Rust)
        ▼                                    ▼
   Sink.lower/verify (taskgate — engine-agnostic)
        ▼
   TorchSink / HostTensorSink / OnnxSink / KernelSink → deliver
```

`mlopt_orchestrator.optimize.search` (`optimize.py:522`) already has
the `engine=` port (`ports.Engine` protocol, `ports.py:1085`) — the
seam exists; engine-eqsat needs an adapter, not a new pipeline.

### What engine-eqsat has today (landed, verified in repo)

- `SearchEngine` trait (`saturate`/`optimize`/`name` over `LawSet` +
  `CostSpec` data) with `EGraphEngine` sole impl — `src/engine.rs`.
- `LAW_FORMAT=2`-shaped law records: `law::to_data`/`from_data`,
  `LawSet::from_json`; `cond`/`dspec` guards **defer** —
  `GuardUnsupported` until stage-2; `missing_hooks`/`serializable:
  false` refuse loudly — `src/law.rs`, `lawset.rs`.
- `CostSpec` kinds `count`/`size`/`op_table` — `src/cost.rs`.
- Corpus: `laws/simplification.json` (18 records) + `builtin.rs`
  (~28 guard-free laws: comm/assoc/id, silu/softsign/square folds,
  matmul/linear assoc+factor, qkv_fuse, distribute/factor).
- Boundary contract: public API speaks only `hnl_engine::Term`;
  `handl_egraph::Term` stays internal (`lib.rs` docs).

### The gaps, concretely

1. **Term bridge (Python ↔ kernel Term).** `hnl_codec.term_to_json`
   already lowers an mlopt term to the kernel-Term JSON envelope —
   that *is* the bridge format. Missing pieces: (a) the attrs channel
   still rides `lit.__mlopt_attrs__`; `Term::Op.attrs` has landed
   upstream so the codec should switch to the canonical `attrs`
   field; (b) **no callable engine-eqsat from Python** — the crate is
   pure Rust, no PyO3. Options: PyO3 optional package (the
   `mlopt-native` precedent — one `optimize()` FFI call per search,
   hot loop stays in Rust) vs `hnl-run`-style subprocess over Term
   JSON (the `mlopt-kit` precedent — viable since a search is one
   saturate+extract call, but loses streaming/progress and doubles
   serialization). **Recommend PyO3** — search is latency-sensitive
   and the Engine protocol is already a Python trait.
2. **Law bank port.** `DEFAULT` = 134 rules + carriers +
   `minted.db` AUTO_TIER vs ~46 laws in engine-eqsat today.
   `laws.serialize LAW_FORMAT=2` is already the shared record format
   — port = transcode patterns to `Pat` JSON + interpreter coverage.
   Guarded majority needs stage-2 (shape-reading predicates + Rust
   shape inference reproducing `mlopt_core.typing`'s 1,913 lines of
   broadcast/None-dim/mm conventions — the single biggest port risk).
   Procedural `check=`/`derive=` hooks (concentrated in
   attention/layout; `conv_bn_fold` is the named example) stay
   `missing_hooks` — those laws' consumers keep the Python engine.
3. **Cost parity.** `count`/`size`/`op_table` cover the simple models;
   `flops_cost` needs shape inference (stage-2); `param_bytes`,
   `executor_*`, `fusion_*`, `roofline`, `lowering_aware` are
   backend-profiled and correctly deferred as named specs — but
   **extraction under a poorer cost picks different members**. The
   verify gate keeps this honest (a worse term still verifies or
   declines) but measured wins can regress. Needs a cost-spec parity
   plan *before* the default flip, not after.
4. **Engine-feature gaps** (each needs port-or-decline):
   - `policy=` in-search action ordering (`EGraph.run(policy=...)`)
     — no `SearchEngine` equivalent; used by strategies.
   - `truncation_level` bounded-member semantics + `nonlocal_passes`
     (already skipped for non-EGraph engines — precedent exists).
   - causal-mask const fold (opt-out pass — wrapper or port).
   - `ProofEdge`/merge-log certificates (`proof.py` 709 lines) —
     ADR-0177 defers to P3+; cert consumers stay Python-side.
   - minted-record admission loop writes `minted.db` — the
     `AUTO_TIER → LAW_FORMAT=2` projection must exist for engine-eqsat
     to see machine-admitted laws.
5. **Consumers to rewire** (all behind `Optimizer.search`/`engine=`
   or direct `EGraph` use): `mlopt_orchestrator.optimize` (+
   `regime`/`autotune`/`compositional`/`diagram_search`/`cache`),
   `mlopt.deliver{,_game,_train}`, `mlopt.stage` search,
   `mlopt_discovery` game arms (`pipeline.propose` saturation —
   measurement arms may *stay* on the Python egraph as oracle),
   `kernelopt.board` (own `lib_kernel_ir` search — unaffected),
   `mlopt-carriers` carrier sets (compose into `rules=` — need
   serialization to `LawSet`).

### Demotion stages (recommended)

- **D1 — parity corpus.** engine-eqsat `optimize` vs `EGraph` on the
  discovery corpus + real-model lifts, under `count`/`size`/
  `op_table`, differential-extracted terms compared. This is the
  ADR-0177 §migration "differential-test" harness — build it in
  engine-eqsat's `tests/` or a bench driver.
- **D2 — `engine="eqsat"` opt-in.** PyO3/Opaque-term adapter behind
  `ports.Engine`; orchestrator unchanged otherwise. EGraph remains
  default + oracle.
- **D3 — feature catch-up.** Guarded-law batches (stage-2), cost
  specs (`flops` post-shape-inference, `op_table` for the shipped
  `_OP_FLOPS`-style tables), policy-ordering decision (port or
  documented decline), AUTO_TIER projection.
- **D4 — default flip (measured).** Only when differential parity +
  no verify-gate regressions on the bench suite. Then `mlopt_core.
  egraph` demotes to spec/oracle (tests + differential harness only).
- **D5 — `mlopt_core.ir` view demotion.** The bigger lift: Sources
  (torch FX lift, OnnxSource, hnl codec) and Sinks currently produce/
  consume `mlopt_core.ir` terms. End-state they produce/consume
  kernel `Term`s directly (the codec already round-trips; the typed
  `TensorType`/`Var`/`Param` view becomes either a thin Python view
  over Terms or is inlined into adapter code). `term_to_data` retires
  with it; `hnl_codec` is the surviving serialization.
- **D6 — retire** `mlopt_native` (superseded), Python egraph proper,
  procedural-hook laws that were never re-expressed (named declines).

## 3. Consolidation design — the end-state table architecture

### Recommendation: two artifacts, one direction

Keep **two** canonical artifacts with distinct authority — do not
merge them into one blob:

1. **`tensor` fragment `ast.yaml` (+ `index.hnl` handwritten decls +
   `aten_schemas.json`/`aten_port_list.txt`)** — the canonical op
   *language*: name, signature, attrs, guards, shape semantics.
   Lives in host-tensor; extended (not replaced) by the fragment
   mechanism. This is "ops are data" (invariant 6) made literal.
2. **`graphopt/vocab/`** (generalized beyond discovery) — canonical
   *records*: laws, handlers, prims, schemas, models, families. Already
   generated+guarded; becomes the source Python views project *from*.

`host_surface.json` stays what it is — a **generated read-model** for
drift guards, never canonical. Same for `aten_classify.py`
(generated), `vocab/*.yaml` projections (`ast.yaml`/`transforms.yaml`
are generated *for* handl consumers — keep them generated).

### What generates the Python-side views

Extend `vocabdir`'s collector pattern into a single
`emit_views` pass (scripts/, like `emit_vocab_fragments.py`):

- op manifest → `opmeta.REGISTRY` rows, `ATTR_SCHEMA`, shape-rule
  registrations (`opdata.declare_op` already proves the seam),
  `HOST_BINDINGS` *positional spec* (data; thin interpreter keeps the
  ~10 procedural builders), `emit._OPS` call-shapes where declarable.
- laws/handlers/prims → `LawSet` JSON for engine-eqsat (kit-eqsat)
  *and* the Python `Rewrite` view during transition.
- ONNX maps → generated from `onnx-ir`/installed schemas with a
  `--check` gate (the `torch_port_gen.py` pattern).

### Where drift guards live

One guard per artifact↔view edge, all `--check`-style in tests:
`test_vocabdir.py` (exists), `test_host_surface.py` (exists),
`test_emit_surface.py` + `test_surface_table_drift.py` (exist),
`torch_port_gen.py --check` (exists). **Add:** onnx opmap/liftmap
generator+check; `stage.py` record `schema:` pin; a single
"manifest→views" freshness test asserting every Python registry
equals its generated projection (the union property — tighten, never
lower).

### Deletion order

1. Flip `pipeline.propose`/game consumers fully onto `load_vocab`
   (auto-resolve already defaults to `vocab/` — verify no
   `vocab_dir=False` production path remains), then delete the
   Python owner tables *last* (they are the oracle until D4).
2. `mlopt_onnx` opmap/liftmap → generated (only unguarded codec
   table).
3. `hnl_surface._SPECS`/`modelproj`/`emit._OPS` call-shapes → manifest
   data; procedural builders stay, named.
4. `HOST_BINDINGS`/torch overrides → data tables + interpreter.
5. One term codec: `hnl_codec` envelope canonical; `term_to_data`
   demoted to view codec, retires with `mlopt_core.ir` (D5).
6. `mlopt_core.egraph`/`mlopt_native` retire post-parity (D4/D6).

**Can start NOW:** WP0a, WP0b, the unconditional-law port subset,
the ONNX generator, the census test, ADR-0178 ratification.
**Must wait:** guarded-law mass port (stage-2), default flip
(stage-3+measured), `mlopt_core.ir` retirement (adapters still emit
it), repo renames (ADR-0175 phase gates).

### Top risks (honest)

1. **Shape-inference parity** — the Rust port of `typing.py`
   semantics is the critical path; budget differential tests per
   predicate family, not one big-bang.
2. **Cost parity** — extraction is only as good as the price; a
   cheaper-but-different cost model silently changes what ships.
   Keep `EGraph`+full cost algebra as the reference until a
   `CostSpec` covers the shipped models *and* matches on the corpus.
3. **Feature-gap honesty** — `policy=` ordering, `truncation_level`,
   causal fold, certs: each is a named decline or a port; none may
   be silently dropped (the `missing_hooks` posture applied to
   *features*, not just hooks).
4. **Two-IR transition tax** — every adapter/sink touched twice
   (ir→Term, then Term-native). Minimize by making `hnl_codec` the
   *only* translator and keeping `mlopt_core.ir` a pure view.
5. **`mlopt_native` overlap** — two Rust search engines for a window;
   retire it at WP4, don't let it become a third permanent path.
