- [ ] T-007 The interpreted typecheck model is the remaining suite bottleneck. After the loader fix above (64.5 min → 25 min), the leftover slow tests are all ones that reach the Handl typecheck model: kit-canonical 's fp\_integration (worst single test 175 s ) / ordered\_annotations (~121 s), and plugin-engine-typecheck-handl::dependent\_structure (~40-60 s each at ~2 GB RSS). Measured inside HandlTypecheckEngine::typecheck on data\_typecheck\_sees\_desugared\_block (the 175 s case) — so the cost is neither marshalling nor loading: - ensure\_model = 305 ns (cached) - marshal\_language (~31k nodes) = 6.2 ms - marshal\_ast = 0.2 ms - model func.call = the remaining ~175 s The model ( typecheck\_model.hnl , ~51k chars) is evaluated by the tree-walk interpreter with a fixed fuel budget and O(n²) tendencies — as the code already says: "measured at minutes even for a 9-node AST, so it is unusable as a default CLI path". On these ASTs it burns the budget and then degrades to the Rust bootstrap checker anyway, i.e. the 175 s is pure waste. Root wiring: only "handl" (the model) is registered as a typecheck engine ( build\_kit ), with model\_enabled defaulting to true ( plugin-engine-typecheck-handl , line 98), so every kit.runtime().typecheck() runs the model. The kit yaml's runtime.typecheck: nbe names an engine that no longer exists. Fix path (deliberate, cross-cutting — not rushed): register the runtime typecheck engine with .with\_model\_enabled(false) so runtime().typecheck() takes the fast bootstrap path, keep the model enabled only for the explicit Kit::typecheck\_handl\* entry points (which already own the model↔bootstrap fallback), and give Kit::typecheck the same bootstrap fallback on NotImplemented . Two things checked on the way, so they need not be re-tried: 1. The fuel budget is not the lever. It is fuel: 50000 in project/design/adr0103/typecheck\_model.hnl , and 50000 ≈ 175 s, so lowering it to 5000 looked promising — but the 565-node data Nat AST still took >90 s. The cost is per-node model work, not fuel steps. (Exhaustion is graceful: it emits a typecheck fuel exhausted diagnostic and a type.unknown , it does not raise.) 2. .with\_model\_enabled(false) on the runtime engine would break Kit::typecheck . Its unit tests assert model-produced types — kit.typecheck("42").unwrap() → type.number , plus type.bool , function types, do { x :: 1; x } , match , x ~: type.string mismatches, ~20 assertions in kit-canonical 's test module — and the bootstrap checker does not synthesize a type (the existing NotImplemented fallback in typecheck\_handl\_with\_prelude returns Value::Null , not report.typ ). So the wiring fix needs a source-level bootstrap type synthesiser behind the fallback first; without one it trades the slow tests for ~20 broken ones. Measured reference points: 3-node AST — model succeeds in 7.65 s ; 565-node data Nat AST — model burns 175 s and reports fuel exhaustion. So the model is only viable for very small ASTs, which is also what a tightened MAX\_MODEL\_NODES would encode (currently 1000, far above where the model stops being viable).
